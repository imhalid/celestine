# The languages of the window: the plan

Celestine is shown in English and Turkish today; Japanese, Chinese and Arabic come next. This note is the plan for
the ground under all of them, decided on 2026-11-11 and tracked in the epic #329. It is a priority: no new
language is added, and no large screen is written, before its first two phases are done.

## Where it stood before the work (2026-11-11)

- `T("…")` (i18n.go) takes the shown text itself as the key. The older strings are written in Turkish with their
  English in `enText` (i18n.go, i18n_more.go, i18n_find.go); the newer ones in English with their Turkish in
  `trText` (i18n_tr.go). Two source languages, and `T` guesses the direction from the text: about 714 `T` and 66 `Tf`
  calls, near 500 entries.
- `lang` is "tr" or "en"; `setLang` makes everything else English.
- Dates already come from MyGo's CLDR data (dates.go, #302): month and day names, the first day of the week, the
  order of a date.
- What breaks with a third language (UX-03 #218, UX-04 #219):
  - a key has no context: one Turkish text with two meanings gets one translation ("Yeniden başlat" is the
    updater's "Restart" and the welcome's "Start again"); a trailing space in the key is the workaround;
  - behaviour is read from Turkish text: a notice's kind from its suffix (toast.go), the palette's groups from title
    prefixes (palgroups.go), menus filtered by a title, the recent commands and custom keys stored by the translated
    title;
  - sentences put together from pieces (`T("Satır ")+n+T(", sütun ")+m`), which no other word order survives;
  - no plural rule (Japanese and Chinese have one form, Arabic six);
  - many strings never pass through `T` (33 buttons, the update dialog, the tour, tooltips, templates that write
    Turkish into the page), and the tests check that a text is in the dictionary, not that it is translated;
  - key hints are Mac glyphs on every system; user data is created with Turkish names ("Adsız", "Liste").

## What is built

MyGo has what is needed, and the app uses none of it yet: `mygo/i18n` catalogs (a JSON file per language, ICU
MessageFormat with plural and select, CLDR plural rules, number and date formats), `mygo generate` for typed
functions over a catalog, `mygo i18n check`, `mygo.App.SetLocale`, the pseudo locales en-XA (accented, a third
longer) and ar-XB (right to left), `Tester.SetLocale`, and `Context.Direction` with logical start and end.

1. **A message is named, not quoted.** Every message has a stable id, grouped by its screen: `update_title`,
   `update_skip`, `settingsUpdate_lastChecked` (a letter, then letters, digits and `_`: MyGo keeps a dot for a key that
   changes a library's message, `mygo.cancel`). Its source text is English, the one source language, with a
   description for the translator where the meaning is not plain. The same English in two places with two meanings is
   two ids.
2. **One catalog per language**, `locales/en.json`, `locales/tr.json`, then `ja.json`, `zh-Hans.json`, `ar.json`,
   embedded in the binary and registered with `mygo/i18n`. A message missing in a language falls back to English
   (the catalog's parents, then the source).
3. **Typed calls.** `mygo generate` writes a function per message (`msg.UpdateTitle(version)`), so a wrong id or a
   missing argument fails the build, not the screen. Should its output not fit the app (it is made for apps with a
   `mygo.json`), a small generator of our own in `scripts/` writes the same.
4. **A sentence is one message.** Values are placed by the message: `{count, plural, one {# page} other {# pages}}`,
   `Line {line}, column {col}`. No text is joined from translated pieces.
5. **Behaviour does not read text.** A notice is given its kind (`a.note(kind, msg)`); every command has a stable id,
   and the palette's groups, the recent commands, custom keys and menu filters use it.
6. **Formats by locale.** Numbers and dates through `mygo/i18n` and the region; key hints written for the system
   (⌘ on macOS, Ctrl and Alt elsewhere) by one `keyLabel`; names the app gives to new user data in the language of the
   moment they are made.
7. **A language table**: code, name in itself, direction. The first start takes the system's language when it is one
   of them; Settings change it.
8. **Tests that hold the line:**
   - every catalog has the source's ids, arguments and its language's plural forms (`mygo i18n check` in the gate,
     and a Go test);
   - no string literal with letters is given as the label of a button, a dialog's title, a setting's row or a
     tooltip unless it is a message (an AST test over the app);
   - every dialog and screen is drawn in en-XA and inspected for text that is not accented (not translated) or is cut;
   - the main screens are drawn in ar-XB, for what does not mirror.

Phases 1 and 2 are one line of work and go first; 3 to 5 can follow in any order once 1 is in; 6 waits for 1 to 5.
The update screens' strings (#324) are written as messages from the start.

## Where phase 1 left it (#330)

- `locales/en.json` and `locales/tr.json` hold the 1105 messages of the old dictionaries word for word (a test went
  through every one in both languages before they were removed), with ids made from the English. The fmt verbs stay
  as they were (`%d`, `%[2]d`) until phase 2.
- `mygo.json` names the catalogs; `mygo generate` (the mygo command of the MyGo version go.mod requires:
  `go install github.com/egoist/mygo/cmd/mygo@<that version>`) writes `locales/catalog_gen.go`, the typed functions.
- `T` finds a text's message through `codeKeys` (i18n_keys.go) and formats it from the catalog in `lang`; the table
  `languages` is the window's languages; `setLang` tells MyGo (`mygo.App.SetLocale`, from main only), so MyGo's own
  words follow the window and not the system.
- The first start does not take the system's language: CLAUDE.md keeps the app English unless Turkish is chosen, and
  that stays until the maintainer decides otherwise.

## Where phases 2 and 3 left it (#331, #332)

- Every word the window shows is a message. The code calls it by its function (`locales.UpdateVersionAvailable(v)`),
  named by screen (`update_`, `settings_`, `palette_`, `common_` for the shared ones); a table that keeps a message
  (a command's title, a setting's name, a block kind, a menu's entry) keeps its id and says it with `msg(id)`;
  "id: value" says the id and keeps the value ("collectionSettings: Books" → "Collection settings: Books").
  `names(id)` are its words in every language, so a setting or a command is found by its Turkish name in the English
  window too. There is no T, no Tf, no codeKeys.
- A sentence with values is one message with named arguments and plurals; times and dates are written by the locale.
  Words that go into the user's data (a new page or collection, a callout, a table's columns, a template, the
  journal's views) are said in the language of the moment they are written.
- Notices tell their kind (`a.say(kind, text)`); nothing reads a kind, a group or an identity from shown words. The
  palette keeps a command by its id; its groups are a table by id (`cmdCategory`).
- Turkish stays only where it is data, not words: what the sync Worker answers (`serverError` maps it), a backup's
  kind in its file's name (`backupKind`), the words a user types for a date, a value or a search, the stats' CSV.
- Tests: `TestCatalogs` (every language has every message, each parses and is said), `TestNoLiteralWords` (no
  literal with letters given to what the window shows), `TestNoIDShown` (no screen shows an id where its words
  should be), `TestPaletteInEnglish` (the palette's modes and the menus have no Turkish line in English).
- Settings kept from before this (the recent commands, the keys of one's own, a pointer effect's or a caret's name)
  were kept by Turkish texts; they are kept by ids now, and older ones are not read back.

## Rules

- A new string is a message with an id in `locales/en.json`, written in English, never a literal in a view.
- A sentence with values is one message; a count is a plural.
- Code never decides anything by a text that is shown.
